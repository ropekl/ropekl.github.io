Prepare and maintain GitHub

Maintainer preparation only

This page is for maintaining Strange Country. It is intentionally not linked from the ordinary help home.

The completed system uses:

  • strange-country-source — private Hugo source, writing, commands, guides, and protected publication snapshot;
  • USERNAME.github.io — public generated website only.

The owner’s connected computer should never be asked to create repositories, configure Pages, add deploy keys, manage Actions secrets, or install downloaded update ZIPs.

Initial GitHub preparation

On a separate trusted computer, remain signed out of account-wide GitHub CLI access when using another person’s account. Sign into the owning account only in the browser.

Create an empty private strange-country-source repository and an empty public USERNAME.github.io repository. Then run:

strange-country connect-github-preparation USERNAME

The helper creates repository-specific keys, configures the encrypted publisher secret, writes the production settings, initializes Git, prepares the protected publication snapshot, and pushes the first source build.

In the public repository, configure Pages to deploy from main and /(root).

Normal maintenance

Git is the normal update channel. Make changes in a Git-connected source repository, run:

make check

then commit and push the tested changes. The owner receives them with:

strange-country update

No package number or manually maintained release counter is required.

make check runs the permanent regression tests before the complete site validation.

Configuration boundaries

config.toml contains site-specific Hugo values. site-config.toml contains the repository and deployment settings for this Strange Country site. Package updates preserve both files.

Managed Hugo behavior lives in system-config.toml. The tested Hugo version and verified release SHA-256 digests live in toolchain.toml. Those managed files may be changed by a tested system update.

Create an update package

A downloaded package is a secondary maintainer/recovery channel. It is not required for ordinary Git updates.

After committing tested system changes that have not yet been pushed to the private source, run:

make package

This creates a minimal three-way update ZIP in dist/, plus a .sha256 file containing the archive digest. The package contains only its updater, verifier, and files that actually changed. Private writing and site-specific configuration are not included.

The package verifier checks the recorded SHA-256 state of every payload file before using the package metadata. Git provenance and per-file old/new hashes determine whether each requested change is safe to apply. The separate .sha256 file can be retained or sent through a separate trusted channel when an out-of-band archive checksum is useful.

The package itself is still trusted according to where it came from. Strange Country does not add a separate maintainer signing key because that would introduce key custody and recovery requirements for a channel that is secondary to the authenticated private Git repository.

Create a fresh installer

For a fresh-computer handoff package, run:

make installer

This creates a separate installer ZIP and SHA-256 file. The installer contains the project and an empty starter writing workspace, not private articles from the maintainer’s working copy.

Install a downloaded update on the connected maintainer master

The connected master must remain at:

Documents/Strange Country

Do not replace or rename that folder. It contains the Git connection and authoritative writing workspace.

Unzip the update package somewhere outside the connected master, open Terminal in the extracted folder, and run:

./update-strange-country

The updater automatically:

  • verifies the package payload before using its metadata;
  • rejects unsafe or escaping package paths;
  • checks only the files the package actually needs to change;
  • stops before modifying anything if one of those files has been changed independently;
  • leaves unrelated local system changes alone;
  • privately backs up all current writing;
  • confirms that the connected master and GitHub are synchronized;
  • creates a dated safety ZIP with private file permissions;
  • preserves site-specific settings, the publication snapshot, PGP key, writing, and images;
  • applies the changed system files atomically, including deliberate removals;
  • refreshes the Terminal command;
  • runs strange-country doctor;
  • commits only the files belonging to this system update and its protected publication snapshot;
  • starts the public deployment.

For each file changed by the package, the installed copy must either still match the expected starting version or already match the new version. Unrelated files do not have to match a particular historical package.

Inspect before installing

./update-strange-country --check

This verifies the package, the GitHub connection, and whether each requested file change is safe. It does not change anything.

Deployment security

The deployment workflow pins actions/checkout to an immutable commit, uses a fixed Ubuntu runner image, does not retain checkout credentials, and installs the checksum-verified Hugo binary without sudo.

Publishing to the public repository uses a repository-scoped deployment key. The connected computer does not require account-wide GitHub CLI authentication merely to report publication progress.

Strange Country polls strange-country-deployment.txt in the public generated-site repository for the exact private-source commit, then polls the same marker on the live website. Private Actions access, when already available, is used only as an optional diagnostic.

Deployment diagnostics are intentionally minimal. Strange Country keeps at most one ~/Library/Logs/Strange Country/deployment-check.txt file, only when deployment verification encounters a problem. A later verified successful publication removes it.

Failure behavior

Package and Git updates stop rather than overwrite conflicting work. Before system files change, Strange Country creates a safety backup. Rollback restores only the update’s own files and does not run a broad git clean, so unrelated untracked maintainer files are left alone.

Owner writing operations likewise stage only the files belonging to that operation. An unexpected system-file change is not silently swept into an ordinary Backup or Publish commit.

iA Writer document opening

Strange Country creates and validates the exact physical Markdown file before asking macOS to open it in iA Writer. That physical file is the authority. The command does not attempt to expand folders, select sidebar rows, wait for iA Writer indexing, send Library URL commands, inspect Accessibility state, simulate input, or read iA Writer’s private database.

Title changes close iA Writer before the folder and document are renamed, validate the change transactionally, and reopen the exact renamed physical file after success.
