    Troubleshooting and recovery

    Return to website help

    Start here

    Open Terminal and run:

    strange-country doctor

    Read the first line marked with ! or Error. Most failures leave the existing public website unchanged.

    “command not found: strange-country”

    Close every Terminal window and open Terminal again. If the command remains unavailable:

    1. confirm the project is at Home → Documents → Strange Country;
    2. in Terminal, run:
    cd ~/Documents/"Strange Country"
./scripts/install_command.sh
    1. close every Terminal window and open a fresh one.

    See Install Strange Country on a Mac for the complete sequence.

    “Strange Country could not find its project folder”

    The folder was moved or renamed. Put it back at:

    Home → Documents → Strange Country

    If the intended permanent location truly changed, rerun ./scripts/install_command.sh from inside the project folder.

    “Hugo is not installed” or “Python 3 is required”

    The one-time setup is incomplete. Follow Install Strange Country on a Mac and run the setup script again.

    The preview will not stop

    Click the Terminal window in which the preview is running and press Control-C once.

    The browser cannot connect to localhost

    The preview or guide command is not running. In Terminal, run either:

    strange-country preview

    or:

    strange-country guide

    “No article matches…”

    Run:

    strange-country status

    Copy the exact article title from the right column and put it in quotation marks.

    “More than one article matches…”

    The shortened title is ambiguous. Run strange-country status and use the complete title in quotation marks.

    An image is missing

    Confirm that:

    1. the image is in the same article folder as index.md;
    2. the Markdown filename exactly matches the real filename;
    3. capitalization matches;
    4. the file extension matches, such as .jpg, .png, or .webp.

    The publish command deliberately stops when a referenced local image cannot be found.

    “GitHub contains newer changes”

    Run:

    strange-country update

    Then preview and publish again. Do not force-push.

    “This Mac has saved changes that are not yet on GitHub”

    Run:

    strange-country save

    Then run the update again.

    The update says the same file changed in two places

    Nothing was overwritten. The message lists the overlapping files and the automatic ZIP backup in Documents → Strange Country Backups. Preserve the message and ask for technical help rather than forcing the update.

    GitHub sign-in uses the wrong account

    Do not continue with account-wide authentication. On a permanent authoring Mac, sign out and sign into your own account. On a different preparation Mac, use the browser-and-repository-key setup instead of signing the Mac into somebody else’s account.

    Publication succeeded, but the public site has not changed

    Open the private source repository on GitHub and select Actions. A green check means the automated deployment succeeded. A red mark means the build needs attention.

    The site looks broken after publishing

    Run:

    strange-country undo

    Read the displayed latest change carefully. Type UNDO only when that is the change that should be reversed. Seek technical help before republishing.

    Nothing here solves the problem

    Do not experiment with Git reset, force push, repository deletion, deploy keys, Actions secrets, or files inside public. Preserve the exact Terminal error and take a screenshot with credentials and private information cropped out.
