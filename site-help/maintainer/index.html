Prepare and maintain GitHub

Maintainer preparation only

This page is for the person preparing and maintaining Strange Country. It is intentionally not linked from the ordinary help home.

The completed system uses:

  • strange-country-source — private Hugo source, drafts, commands, guides, and protected publication snapshot;
  • USERNAME.github.io — public generated website only.

The owner’s connected computer should never be asked to create repositories, configure Pages, add deploy keys, manage Actions secrets, or install downloaded update ZIPs.

Initial GitHub preparation

On a separate trusted computer, remain signed out of account-wide GitHub CLI access when using another person’s account. Sign into the owning account only in the browser.

Create an empty private strange-country-source repository and an empty public USERNAME.github.io repository. Then run:

strange-country connect-github-preparation USERNAME

The helper creates repository-specific keys, configures the encrypted publisher secret, writes the production settings, initializes Git, prepares the protected publication snapshot, and pushes the first source build.

In the public repository, configure Pages to deploy from main and /(root).

Install a downloaded build on the connected maintainer master

The connected master must remain at:

Documents/Strange Country

Do not replace or rename that folder. It contains the hidden Git connection and authoritative writing workspace.

Download and unzip the new build in Downloads. In Terminal, enter the extracted folder and run:

./update-strange-country

For example:

cd ~/Downloads/strange_country_106
./update-strange-country

The updater automatically:

  • privately backs up all current writing;
  • confirms that the connected master and GitHub are synchronized;
  • creates a dated ZIP backup in Documents/Strange Country Backups;
  • preserves .git, the repository-specific SSH connection, site-config.toml, config.toml, the protected publication snapshot, PGP key, Posts, Misc Musings, About, and all images;
  • runs any required author-workspace migration;
  • replaces only the managed website system files;
  • refreshes the zsh command;
  • runs strange-country doctor;
  • updates the protected public snapshot;
  • commits and pushes the tested build;
  • starts the public deployment.

The live site may take a few minutes.

Inspect before installing

./update-strange-country --check

This reports the connected master, current build, package build, GitHub remote, and planned actions without changing anything.

Failure behavior

The updater refuses to continue if it cannot identify the connected master, if the package is older than the installed build, if GitHub and the computer disagree, or if the complete site check fails. Before changing system files it creates a backup. If installation fails before the tested update is pushed, it resets the connected master to the previous saved Git state.

Send the tested update to the owner’s computer

After the package updater succeeds, tell the author to run:

strange-country update

That command downloads the tested changes, protects unfinished writing, refreshes the Terminal command, runs migrations, and performs a complete build. No raw Git command is needed.

iA Writer navigation safety

For a new Post or Misc Musing, Strange Country creates the exact physical Markdown file atomically before opening iA Writer. It opens that file first, waits on observable readiness signals with a strict timeout, makes one documented Library-path request, and opens the physical file again as the final editing target. It does not use Accessibility clicks, GUI scripting, simulated keystrokes, or iA Writer’s private database.

Because iA Writer exposes no documented callback for completed Library indexing or visible sidebar selection, the owner is shown the exact Writing path and must confirm that the document—not merely its folder—is visibly selected before the command reports success. A no answer closes Writer normally and leaves the private piece safely on disk. This is the fail-closed boundary; file safety never depends on a guessed delay.

Existing documents use the same documented Library-path command bracketed by physical-file safeguards. Title changes continue to close Writer before renaming anything.
