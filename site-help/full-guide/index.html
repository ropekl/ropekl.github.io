    Write, save, preview, and publish articles

    Return to website help

    1. The four everyday commands

    strange-country new "Article Title"
strange-country save
strange-country preview
strange-country publish "Article Title"
    • New creates a private draft and opens it in iA Writer.
    • Save backs up drafts and edits privately.
    • Preview shows the website only on your Mac, including drafts.
    • Publish updates the public website with one named article.

    2. Open the project

    Keep the project at:

    Home → Documents → Strange Country

    Open a fresh Terminal window and type:

    strange-country

    Other strange-country commands work from any folder, so you do not need to navigate manually before using them.

    3. Understand the posts folder

    Add this one location to iA Writer:

    Documents/Strange Country/content/posts

    It has one simple purpose: it holds your articles.

    posts
├── first-article-title
│   ├── index.md
│   └── photograph.jpg
├── second-article-title
│   ├── index.md
│   ├── chart.png
│   └── portrait.webp
└── third-article-title
    └── index.md

    Follow these rules:

    1. Every article has its own folder directly inside posts.
    2. The folder name is made automatically from the article title: lowercase words separated by hyphens.
    3. The article’s writing file is always named index.md.
    4. Images used only by that article go in the same folder as index.md.
    5. Do not rename an article folder or its index.md file after creation.
    6. Do not place loose .md files directly inside posts.
    7. Do not create subfolders such as Drafts, Published, Politics, or Technology. Draft and publication status are handled by the article metadata and commands.

    The safest rule is: never create or name an article folder by hand. Use the new-article command and let Strange Country organize it.

    4. Create a private draft

    Type:

    strange-country new "Exact Article Title"

    Always put the title in quotation marks. The command:

    • creates the article folder;
    • gives the folder a safe web-friendly name;
    • creates index.md with the correct metadata;
    • marks the article as a private draft;
    • opens index.md in iA Writer.

    The top of the file resembles:

    +++
title = "Exact Article Title"
description = ""
date = "YYYY-MM-DD"
tags = []
categories = []
slug = "exact-article-title"
type = "post"
draft = true

[params]
location = ""
+++

    Write below the second +++ line. Do not delete or rearrange the front matter. Do not change slug, type, or the name index.md unless you have technical help.

    5. Write and format the article

    Leave a blank line between paragraphs.

    Headings

    ## Major section

### Subsection

    The page already uses the article title as its main heading, so do not begin the body with a single # heading.

    Italics and bold

    *italics*

**bold**

    Links

    [Words visible to the reader](https://example.com/)

    Block quotations

    > This is a quoted passage.
>
> A second paragraph remains part of the quotation.

    Lists

    - First item
- Second item
- Third item

    Footnotes

    A sentence that needs a note.[^1]

[^1]: The text of the footnote.

    6. Add images to an article

    Put an image in the same article folder as index.md. Use short, descriptive filenames with lowercase letters, numbers, and hyphens:

    platform-moderation-chart.jpg
author-at-conference.webp

    Avoid spaces, punctuation, and names such as IMG_4827 copy FINAL.jpg.

    Insert an image in the article with:

    ![A concise description for readers who cannot see the image](platform-moderation-chart.jpg "Caption displayed beneath the image")

    The filename in Markdown must match the real filename exactly. The square-bracket text describes the image for readers who cannot see it. The quoted text is optional and becomes the visible caption.

    Never place credentials, confidential source documents, or private screenshots in an article folder.

    7. Save privately

    Run:

    strange-country save

    This backs up drafts and edits to the private source repository without changing the public website.

    8. Preview drafts

    Save the article in iA Writer, then run:

    strange-country preview

    The browser opens at http://localhost:1313/. The preview includes private drafts and is visible only on this Mac.

    After the browser opens, Terminal continues to display the stopping instruction:

    To stop previewing, return to Terminal and press Control-C once. This does not change the public website.

    9. List drafts and published articles

    Run:

    strange-country status

    Use this when you cannot remember an exact title or want to see what remains private.

    10. Publish one article

    Before publishing, save and preview the article. Check its title, links, images, captions, spelling, and confidential material. Then run:

    strange-country publish "Exact Article Title"

    Only the named article is copied into the protected public-site snapshot. Other drafts and unfinished edits remain private. If validation or building fails, the existing public website remains unchanged.

    11. Correct a published article

    Open and edit the existing index.md, save it, preview it, and run the same publish command again:

    strange-country publish "Article Title"

    Do not create a second article folder for a correction.

    12. Remove an article from the public site

    Run:

    strange-country unpublish "Article Title"

    The article remains in its folder as a private draft but disappears from the public website after deployment.

    13. Receive website improvements

    Run:

    strange-country update

    This downloads improvements from the private source repository while protecting non-conflicting unfinished writing. See Save your work and receive website improvements.

    14. Files you should edit

    For routine work, edit only:

    • article index.md files;
    • images in the corresponding article folder;
    • the About page when necessary.

    Do not edit or delete .github, archetypes, assets, layouts, scripts, static, config.toml, or site-config.toml without technical help.
